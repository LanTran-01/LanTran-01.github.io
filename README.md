# Ξ Hardware Explorer — www.lantran.dev

An interactive, engineering-style 3D explorer for the RX-105 Ξ (Xi) Gundam from
*Mobile Suit Gundam: Hathaway*. Select an assembly, cut away its armor, explode
its subassemblies, and trace a conceptual systems architecture that stays linked
to the 3D model.

> **Read this first — what is and isn't real.**
> The 3D machine is a **procedural prototype**, a silhouette study built from
> three.js primitives. It is not an accurate or licensed model of the Xi Gundam.
> All internal hardware, subassembly breakdowns and the systems map are
> **conceptual visualizations** invented for this project, not canon. In the data,
> rows marked `reference` repeat only broad, non-numeric descriptors that are widely
> published (for example, that the RX-105 carries a Minovsky flight system).
> Everything else is marked `conceptual`. No engineering measurements, power
> ratings or materials are claimed.
>
> RX-105 Ξ Gundam and Mobile Suit Gundam Hathaway are trademarks of their owners
> (Sotsu · Sunrise / Bandai Namco Filmworks). This is an unofficial fan engineering study.

## Repository layout

```

  index.html         ← generated by `npm run publish:site`
  404.html           ← generated: bounces deep links (/explore/head) to the app
  static/            ← generated JS/CSS/fonts
  CNAME              custom domain (never touched by the publish script)
explorer/            the application source (React + TypeScript + Vite)
```

## Running locally

Requires Node 20+ (installed here with `brew install node`).

```bash
cd explorer
npm install
npm run dev            # http://localhost:5173
npm run typecheck      # tsc, strict
npm run lint           # eslint
npm run build          # production build into explorer/dist
```

## Publishing to www.lantran.dev

GitHub Pages serves the repository root of `main` with no CI step, so the build
output is committed:

```bash
cd explorer
npm run publish:site   # build, then copy dist/ into the repo root and write 404.html
cd ..
git add -A && git commit -m "Publish explorer" && git push
```

`scripts/publish.mjs` only removes files it wrote last time (tracked in
`.site-manifest.json`) and never touches `CNAME`, `README.md` or `explorer/`.
Deep links such as `/explore/head` or `/systems?node=pwr-core` work through
`404.html`, which redirects to `/?redirect=…`. A small inline script in
`index.html` restores the real URL before the router starts.

## Using the explorer

| Action | Input |
|---|---|
| Rotate / zoom / pan | drag · wheel or pinch · right-drag or two-finger drag |
| Select an assembly | click it on the model or in the index |
| Inspection modes | Exterior · Cutaway · Exploded (with distance slider) · Architecture (3D callouts), or keys `1`–`4` |
| Subassemblies | click in the hardware tree, a callout, or on the model in an inspection mode |
| Previous / next assembly | `←` / `→` |
| Back / reset | `Esc` (clears the subassembly first, then returns to the full machine) · `R` resets the camera |
| Systems map | `/systems`: click a node to highlight its linked assemblies in 3D; click the model to filter nodes |

Routes: `/` overview · `/explore/:slug` (head, cockpit, shoulders, arms, waist,
legs, feet, backpack, thrusters, weapons) · `/systems?node=<id>`.

## Architecture

The 3D canvas is mounted once in `AppShell` and never remounts. Routes only
render overlays, so moving between assemblies and the systems map keeps the
scene, the camera and the loaded model.

```
explorer/src/
  data/                        typed content, the single source of truth
    components.ts              10 assemblies, subassembly trees, tech data, camera hints
    subsystems.ts              conceptual systems graph (nodes, flows, lanes)
    modelConfig.ts             model source, GLB path, mesh-name → assembly rules
  state/explorerStore.ts       zustand store (URL owns selection; store owns mode, hover, explode…)
  features/gundam/
    modelTypes.ts              mesh tagging contract (userData.xi = PartTag)
    procedural/                the procedural prototype (about 230 meshes, 66k triangles)
    loadModel.ts, annotateModel.ts, useGundamModel.ts   procedural or GLB → indexed model
    materialController.ts      per-mesh material state
  features/component-inspection/modeVisuals.ts   exterior / cutaway / exploded / architecture tuning
  features/hardware-architecture/                diagram layout, edge routing, pan/zoom
  components/viewer/           R3F scene, camera rig, interaction, hover label, 3D callouts
  components/inspection/       inspection panel sections (identification, modes, tree, data)
  components/architecture/     systems diagram, node detail, legend, controls
  components/layout|navigation/ top bar, status bar, sheets, index, dialogs
  pages/                       ExplorerPage, ComponentDetailPage, SystemsPage
```

### Replacing the prototype with a real model

1. Put a GLB/GLTF you have the rights to use in `explorer/public/models/`
   (for example `xi-gundam.glb`).
2. Open the site with `?model=gltf`, set `source: "gltf"` in
   `src/data/modelConfig.ts`, or build with `VITE_MODEL_URL=/models/file.glb`.
3. Edit `meshRules` in `modelConfig.ts` so mesh and node names map onto the
   10 assemblies. Meshes are scaled to the target height and placed on the floor.

If the GLB fails to load, the viewer falls back to the procedural prototype and
says so in the status bar. A GLB usually has no internal geometry or explode
vectors, so Cutaway and Exploded are disabled with an explanation for any
assembly that lacks them. The capabilities come from the geometry actually present.

### Dev tools

- `explorer/harness/model.html` is a standalone model inspector with these
  options: `?view=front|side|back|three-quarter`, `?explode=0..1`,
  `?layer=internal`, `?focus=<assembly>`, `?probe=1`.
- `npm run shot -- <url> <out.png> [--w --h --mobile --click --drag --eval …]`
  takes a headless screenshot and reports any console errors. It needs
  `npx playwright install chromium` once.

## Known limitations

- The prototype's proportions are approximate. The pure side view is its weakest
  angle, because the pauldrons hide the head.
- Some data subassemblies (for example `cp-env`) have no geometry. The tree marks
  them "not modelled".
- The thruster array spans the whole body, so its close-up is necessarily wide.
- On narrow phones, the architecture-mode callouts are truncated.
- three.js is pinned to r182. React Three Fiber 9.8 still uses `THREE.Clock`,
  which r183+ deprecates with a console warning.
